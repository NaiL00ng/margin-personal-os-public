# ADR 0002：本机 Python 与 SQLite 持久化

- 日期：2026-11-08
- 状态：本地首版实现；验证结果见[验证记录](../../quality/validation.md)。
- 承接：[ADR 0001](0001-prototype-and-future-backend.md)。
- 范围：便利贴、驻留、历史、导入与备份；不包含记账、账户、跨设备同步或公网部署。

## 决策与原因

用户授权实现 Python + SQLite 后端，要求保留现有界面并只在本地保存。当前环境没有 FastAPI、SQLAlchemy、Alembic，仓库规则不允许自动安装依赖。本版使用 Python 3.9+ 标准库 `http.server`、`sqlite3`、`unittest`，把 HTTP 适配与领域存储分离。此前框架方案仍可作为后续选项；本版没有安装它们。数据库使用显式 schema 版本，未知版本拒绝打开；未来结构升级必须新增受测迁移，不能通过删库重建升级。

Python 只绑定 `127.0.0.1`，通过静态文件白名单提供现有网页，并注入数据库模式标记。浏览器直接打开 HTML 或 Node 静态预览仍使用旧浏览器存储；两种入口清楚区分，数据库不可用时绝不静默切换成浏览器保存。

## 领域与事务

- Python 是数据库模式中已确认业务状态的唯一来源。JavaScript `BoardModel` 用于读取、统计与展示，并保留静态入口兼容性。
- 卡片、过程事件、驻留区间、旧累计基线、分类及设置分别存储。结束快照作为完成／取消事件的不可变内容，不承诺任意历史重放。
- 每次命令在 `BEGIN IMMEDIATE` 事务中检查全局 revision、结算区间、更新卡片、追加事件、递增 revision、写入幂等回执。一次动作全部提交或全部回滚。
- `operationId` 绑定规范化完整请求。同 ID 同参数重试不重复写入；不同参数拒绝。重试返回原动作结果和当前状态，避免旧响应覆盖后续状态。
- `databaseId` 为数据库稳定身份；恢复备份不会改变当前库身份。浏览器待确认请求按数据库身份隔离。
- 采用全局 revision 而非卡片级版本：实现简单，能保护跨卡整理、导入和恢复；代价是两个标签修改不同卡也可能冲突。本版不自动合并冲突。

## 计时与表现

服务端在操作事务中确定有效时间，统一用于区间与事件。页面每秒只更新显示；关闭浏览器或服务不暂停墙钟驻留。同象限移动只改位置，跨象限关闭旧段并开启新段；准备区、调整、完成及取消不继续计时。系统时钟回退不能生成负驻留。

调整一经确认，业务状态就是准备区；暂留副本、落点几何和移动动效仅在 UI 存在。完成和 Void 动效也不决定提交。网络等待时保留落点副本；保存确认后衔接对应效果。关闭／减弱动效不改变事务。

## 导入、备份与恢复

旧 `version:1` JSON 先严格校验、显示预览，再由确认命令导入。保留 ID、外观、坐标、累计、当前起点及已有快照。`residenceStatistics` 是派生统计，不重复入账。旧数据不能证明的历史区间保留为累计基线；同 ID 不同内容拒绝覆盖，重复来源可识别，原始导入证据保留在本机库中。

SQLite Backup API 生成本机一致性快照。恢复预览检查数据库格式和完整性；恢复前自动创建当前库备份，然后在事务中替换领域记录。当前库的身份、递增版本和幂等回执保留，防止重复恢复再次抹掉后续操作。JSON 用于可读导出与合并导入；数据库备份用于完整状态恢复。备份只由受控 ID 选择，不接受任意文件路径。

## 边界

- 请求结果未知时保留同一请求供重试；不把超时直接当作确定失败。未决请求阻止新的正式修改。
- 本版不实现离线命令队列、跨设备同步、登录系统、数据库加密或自动异地备份。
- HTTP 层有 Host／Origin／CSRF／请求体校验及私有文件隔离，但这是本机个人工具，不是公网服务方案。
- 浏览器未提交表单保留在当前页面，尚无独立草稿恢复机制；已确认业务状态在数据库中。
- 本机手动备份与恢复前自动备份已实现；周期性备份尚未实现。同盘副本不能应对整块磁盘损坏。
- GitHub 版本记录与用户数据库分开；本次仅本地开发，无远端提交或发布。

## 产品依据

持久历史支持进度监测与轻量回顾，取消／恢复保留目标调整空间，对应[证据登记](../../research/evidence-register.md) E03、E05、E07。上述论文不证明数据库选型或本产品效果；本次新增能力通过事务、故障、计时和恢复测试验证工程正确性。
