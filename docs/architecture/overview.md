# 架构概览

更新日期：2026-11-08。当前开发版本 `0.3.0-dev.2`，运行时数据仅保存在本机。本文记录实现边界，并单独列出尚未实现的演进方案。

## 当前实现

余白 MARGIN 保留网页看板，加入 Python 3.9+ 标准库 `http.server` 与 `sqlite3` 后端，不安装第三方依赖。`python3 server.py` 默认在 `127.0.0.1:4317` 提供数据库模式；直接打开 HTML 或 Node 静态预览仍使用浏览器存储。两种入口不自动同步，数据库不可用时不静默回退。没有银行连接、真实账单、完整记账、生命月历或日程排程。

| 层 | 当前文件 | 职责 |
| --- | --- | --- |
| 页面与样式 | [index.html](../../index.html)、[style.css](../../style.css) | 四象限、准备区、操作区域、弹窗容器、响应式外观 |
| 前端模型 | [model.js](../../model.js) | 静态入口的领域操作；数据库模式读取已确认状态、展示和统计 |
| 交互适配 | [app.js](../../app.js) | DOM 渲染、拖拽、确认、弹窗、设置、导出及数据与备份界面 |
| 请求层 | [storage.js](../../storage.js) | 数据库身份、版本、操作 ID、待确认请求与重试；不提供离线写队列 |
| HTTP 适配 | [server.py](../../server.py)、[backend/server.py](../../backend/server.py) | 本机入口、JSON API、Host／Origin／令牌校验与静态文件白名单 |
| macOS 图形入口 | [Swift 窗口](../../launcher/MarginLauncher.swift)、[launcher.py](../../launcher.py)、[构建脚本](../../build_launcher.py) | 同项目同数据库健康检查、并发启动锁、服务生命周期、打开浏览器；不实现新的存储层 |
| Python 领域存储 | [backend/store.py](../../backend/store.py) | 状态校验、SQLite 事务、驻留区间、事件快照、导入、备份与恢复 |
| 装饰性反馈 | [effects.js](../../effects.js) | 纸面伪 3D、入场、完成抖动缩小、调整暂留与归位、Void 边缘燃烧、减弱和关闭动效 |
| 单文件交付 | [build.mjs](../../build.mjs) | 将本地资源打包成 `prototype.html`；构建方法与影响范围见 [README](../../README.md) |

源页面依次加载 `model.js`、`effects.js`、`storage.js`、`app.js`。数据库模式以 Python 返回的已确认状态为准；动作等待期间保留必要的界面副本，确认提交后接续效果。静态模式由 `BoardModel` 处理业务变化并写浏览器存储。`BoardEffects` 只处理视觉反馈，动画结束不等于保存成功。单文件构建读取 `index.html`、`style.css` 和这四个脚本，共六个源文件；不会内联 Python 或数据库。

编辑暂留属于界面状态：模型在开始编辑时已结算并存为 `active/prep`，UI 暂时从看板与准备区移除原卡，用非交互副本保留落点。关闭编辑窗后显示准备区目标并转移动效；刷新会从已保存的准备区状态恢复。暂留和转移不写入新的业务象限，不额外累计驻留。

## 当前数据结构

交换数据保持 `version: 1`，静态入口浏览器存储键仍为 `margin.matrix.v1`。数据库结构单独使用 schema 1；服务加载未知 schema 时拒绝打开，没有未来版本迁移引擎，也不会自动删库重建。

| 数据 | 字段与含义 |
| --- | --- |
| 卡片 | `id`、`title`、`description`、`category`；`appearance` 保存纸色、角度、小符号和随机种子 |
| 生命周期 | `status` 为 `active`、`completed` 或 `cancelled`；活动卡片的 `zone` 为 `prep` 或 `q1`—`q4`，结束后为 `null` |
| 象限坐标 | `positions` 按 q1—q4 保存独立 `{x,y}`，范围 0—1，映射为当前画布可用平移空间；仅释放或整理时写入 |
| 时间 | `createdAt`、`updatedAt`、`endedAt`；`startedAt` 是当前象限驻留段的起点，`durations` 保存各象限已结算毫秒数 |
| 过程事件 | `created`、`moved`、`positioned`、`editing`、`updated`、`completed`、`cancelled`、`restored`；含时间及有关分区信息 |
| 结束快照 | 完成或取消事件的 `snapshot` 保存当时卡片内容、外观、原因和已冻结驻留量；后续恢复、修改不覆盖该快照 |
| 设置 | 分类列表、四象限颜色、`motion` 与 `respectSystem` |

`positions` 是兼容性可选字段：旧 v1 数据缺失时读为 `{}`。前端旧存档读取会丢弃无效坐标对；后端导入采用严格校验，有非法坐标则拒绝，不静默修正。存储键和交换数据主版本不变，不重映射象限 ID。旧程序可能在保存时丢弃新字段；回退前应保留导出，不能在两个版本间反复覆盖同一份存储。

当前采用“可变卡片状态 + 过程日志 + 结束快照”，并在数据库保存旧累计基线与已知驻留区间。旧事件可能缺少字段变化或结束快照，导入只提示未知，不补造。它不是可任意重放历史的完整事件溯源系统；快照也不提供密码学防篡改或审计认证。

## 数据库事务与请求边界

- 数据库默认路径为 `.local/margin.sqlite3`；新库为空，不生成示例。`cards`、`events`、`residence_baselines`、`residence_intervals` 保存领域记录，元数据保存分类、设置、稳定 `databaseId` 与全局 `revision`。
- 命令在 `BEGIN IMMEDIATE` 事务中校验、结算、更新状态、追加事件和幂等回执，一起提交或回滚。SQLite 使用 WAL；测试与实际边界见 [验证记录](../quality/validation.md)。
- `operationId` 绑定完整请求。同 ID 同参数重试返回原动作结果和当前状态，不重复提交；同 ID 不同参数拒绝。`expectedRevision` 防止旧状态覆盖新状态，不同卡片也可能因全局版本产生冲突。
- 待确认请求按数据库身份保留，结果未知时用同一请求重试并阻止新的正式修改；这不是积压离线命令的机制。未提交表单只有当前页面内容，没有持久草稿恢复。
- HTTP 只监听本机，提供限定的源文件及 API，不开放数据库／备份文件路径。Host／Origin／令牌校验不等同用户账户或公网部署安全方案。

## 时间语义与状态边界

象限驻留是卡片占据某一象限的墙钟时间。进入象限开始，切换象限结算上一段，准备区和编辑期间暂停，完成或取消后冻结。数据库模式由服务端动作时间统一记录区间与事件；页面每秒只刷新显示。刷新、关闭页面或停止服务不自动暂停，重开后仍使用保存的起点计算经过时间。同一象限重复放置不会重新开始计时；时钟回退不能产生负驻留或倒序历史。

多张卡片可以同时累计，驻留量不能相加后称为工时，也不能据此推断专注、投入、效率或价值。计算不依赖后台秒表持续运行。详细操作关系见 [交互规范](../design/interaction-spec.md)。

## 存储与恢复边界

- 静态入口的 `localStorage` 按浏览器和来源隔离；`file://` 范围由浏览器决定。异常或跨窗口变化时保护已有存储并提示。它不自动成为数据库内容。
- 数据库模式的 JSON 导出包含模型数据、历史、已知驻留记录与派生统计。旧 JSON 预览确认后合并；同来源重复导入可识别，同 ID 不同内容拒绝覆盖。旧累计保留为基线，不因派生统计再次增加。
- `.local/backups/` 使用 SQLite Backup API 保存一致性快照。恢复检查格式和完整性，预览确认后先创建安全备份，再在事务中替换领域记录。当前数据库身份、递增 revision 和幂等回执保留，避免重复恢复再次覆盖后续修改。
- 活动卡片恢复保留备份中的驻留起点，离线期间继续按墙钟计入；恢复不会重演历史动画。JSON 合并导入不能替代数据库状态恢复。
- 尚无定时／异地备份、加密、跨设备同步、离线写入队列或公网账户。同盘备份不能解决整盘故障。操作说明见 [后端指南](../backend-guide.md)。

## 后续领域扩展：尚未实现

当前本机 Python 选择见 [ADR 0002](decisions/0002-local-sqlite-backend.md)；[ADR 0001](decisions/0001-prototype-and-future-backend.md) 保留早期方向与历史边界。后续可沿单一部署单元扩展，不预先承诺新框架、微服务或云服务。

| 候选模块 | 未来职责及必须保留的边界 |
| --- | --- |
| 任务与计划 | 在现有卡片／位置基础上加入日程时间块；计划何时做与真实截止日期分别表达 |
| 实际时间 | 现有驻留区间继续保留；若以后加入专注计时，使用独立记录，不能复用驻留数值冒充 |
| 财务事实 | 账户、交易、转账、退款、来源及核对状态；金额计算采用适合精确货币运算的表示 |
| 预算计划 | 预算分配、目标和预测；计划不是已经发生的交易，转移预算也不等于账户转账 |
| 承诺与回顾 | 可选关联任务、时间安排与交易；未关联的日常行动和消费仍然有效 |
| 存储演进与新来源 | 增加受测 schema 迁移，按需评估备份计划及账单来源；不把已有旧卡片 JSON 导入称作账单导入 |

未来迁移仍须保留卡片标识、驻留语义和历史快照，并先用合成导出样本验证映射。现有示例便利贴不能直接充当财务数据。跨模块统计必须区分事实、计划与用户主观评价，不能计算未经定义和验证的“人生总分”。

这些模块是工程提案，不表示已获产品效果验证。哲学概念可以说明设计目的；某项交互是否减少负担、支持回归或改善实际行动，需要单独的研究依据和使用验证。当前验证范围见 [验证记录](../quality/validation.md)。
