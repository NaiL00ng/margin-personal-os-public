# 本机后端使用与数据保管

当前版本：`0.3.0-dev.2`，服务仅在本机运行。需要 Python 3.9 或更高版本，不需要安装第三方依赖。

## 图形启动器（macOS）

仓库提供启动器源码，不分发带有本机定位信息的 `Margin.app`。下载源码后，如本机已有 Python 及 Swift 编译工具，按本节下方命令构建；没有 Swift 时直接使用后文的 `python3 server.py` 入口。

构建后，在项目文件夹中双击 `Margin.app`：原生小窗口会检查服务，启动完成后自动用默认浏览器打开数据库版看板。之后的日常启动没有终端输入步骤，也不会切换到独立的静态 HTML。

- **快捷入口**：可把 `Margin.app` 拖到 Dock，或在访达选中它，使用“文件 → 制作替身”，把替身放到想要的位置。应用本体建议留在项目目录。移动整个项目时仍可按相邻文件定位；仅复制应用不是完整安装包。
- **关闭网页**：记录已写入 SQLite；服务仍运行，可点启动器的“打开看板”再次进入。
- **停止服务并退出**：只停止本次启动器创建的服务。退出前请等网页显示已保存；下次双击继续读取原库。
- **复用服务**：若该项目同一数据库已经在运行，则直接打开；退出启动器不会关闭原服务。
- **端口占用**：无法确认服务属于本项目及同一数据库时，显示错误并提供重试。不会杀掉其他程序或悄悄切换端口。升级前的旧服务若没有健康接口，请在它原来的终端按 Ctrl+C 停止后重试。

启动器使用本机现成的 Python 与 macOS AppKit；此 `.app` 只为当前 Mac 构建，未签署开发者分发证书或制作跨系统安装包。源码、构建脚本及上一版源文件在项目内保留。需要重建时，在确认本机已有 Swift 编译工具后运行：

```sh
python3 build_launcher.py
```

构建只读取项目源码，并写入项目 `Margin.app` 与 `.local/launcher-build/`，不联网、不安装工具。重建前的应用会移入构建目录留存。应用携带本机定位信息且被 `.gitignore` 排除；发布源码不应上传生成应用或个人数据库。

## 启动

在项目目录运行：

```sh
python3 server.py
```

然后用浏览器访问 `http://127.0.0.1:4317`。顶部应显示“已保存在本机数据库”，并有“数据与备份”按钮。停止服务使用终端 Ctrl+C。下次运行同一命令继续读取原库；便利贴不会因为浏览器或服务关闭而删除。

默认数据库位于项目 `.local/margin.sqlite3`，备份位于 `.local/backups/`。不要把这些目录提交 Git、公开分享或用临时清理工具删除。数据库未加密。

可选参数：

```sh
python3 server.py --port 4318 --db .local/another-board.sqlite3
```

不同 `--db` 是不同数据库。端口被占用时会提示；不要在同一端口同时运行 `preview.mjs` 和 Python 服务。浏览器尽量固定使用同一个地址，避免旧浏览器数据和待确认请求分属不同来源。

双击 `prototype.html` 仍是独立静态模式，仅保存到当前浏览器。它不会自动读取 SQLite，也不会把数据自动上传给 Python。Python 服务只接受本机请求，不提供跨设备同步。

## 导入旧便利贴

1. 在原来使用的浏览器和旧页面中打开“记录册 → 导出完整记录”，保留下载的 JSON。
2. 打开 Python 页面，进入“数据与备份”，选择 JSON 文件。
3. 核对卡片数量、事件数量、警告和错误，再点“确认导入”。本版网页文件上限为 7 MiB。
4. 查看看板、已完成／已取消记录及驻留分布；原文件继续保留。

若旧记录在当前地址的 localStorage 内，会出现“预览此地址下的旧浏览器记录”。其他地址或 `file://` 文件下的记录不能由此按钮跨来源读取，仍需导出 JSON。

导入保留卡片 ID、纸面、坐标和历史；重复导入不复制记录。同 ID 内容不一致时拒绝覆盖并报告错误。未知或坏格式不会被静默过滤。旧记录缺失的精确区间不能恢复为已知历史，使用累计基线保存；导出内的派生统计不再次累计。已有库的偏好不会被旧文件无提示覆盖，具体合并提示以导入预览为准。

## 备份与恢复

“创建当前备份”把数据库一致性快照保存到本机。备份列表可预览卡片和过程记录数量；点击“确认恢复这个备份”后，当前看板和历史会被替换成该备份的状态。恢复前自动保留当前库副本，可从列表再次恢复。

活动卡片恢复后仍沿用备份中的驻留起点，故离线期间会计入驻留。准备区和已结束卡片保持暂停／冻结。恢复不会重放动画，也不会重新抽取纸面。

“导出完整 JSON”可另存可读资料；JSON 导入采用合并语义，数据库备份恢复采用替换语义。备份文件请保留在数据库旁的受控备份目录，不要改文件名或直接编辑内容。损坏或未知 schema 的文件会拒绝恢复。

本版提供手动备份与恢复前自动备份，没有定时任务或异地副本。建议在重要整理后手动备份；升级前保留一份独立副本。备份是否可靠，应通过合成数据或独立数据库的一次恢复核验确认。

## 保存状态与冲突

- “已保存在本机数据库”：服务已确认事务。
- “正在保存”：等待确认，避免重复操作。
- “保存结果待确认”：可能已经提交；使用“重新连接 / 重试保存”，系统会重试同一操作编号。
- “记录已更新”：另一个标签改变了数据库；核对当前状态，表单输入仍保留在当前窗口，可决定是否重新提交。

数据库模式不会在服务不可用时退回浏览器保存。尚未提交的输入框内容没有长期草稿保证，关闭页面前应完成保存或自行保留文字。浏览器中的待确认请求日志用于恢复网络结果，不是离线操作队列。

## 开发与验证

先阅读对应脚本，再运行：

```sh
python3 -m unittest discover -s backend -p 'test_*.py' -v
python3 -m unittest launcher_test -v
node --test model.test.cjs storage.test.cjs
node build.mjs
```

测试只使用合成数据和项目 `.local/` 下独立临时目录，不连接真实账单、不上传网络服务。实际结果和未测范围见[验证记录](quality/validation.md)；接口和事务设计见[ADR 0002](architecture/decisions/0002-local-sqlite-backend.md)。
