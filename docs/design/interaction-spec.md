# 便利贴交互规范

更新日期：2026-11-08。范围为当前静态原型；不是完整个人管理与记账产品的功能清单。

## 空间与信息

主界面由四象限、准备区、调整、完成、Void 和记录册组成。纵轴上方重要、下方不重要；横轴左侧不紧急、右侧紧急。方位采用以下布局，象限编号和原有存档中的业务含义保持不变：

| 方位 | 象限 | 含义 |
| --- | --- | --- |
| 左上 | II / `q2` | 重要、不紧急 |
| 右上 | I / `q1` | 重要、紧急 |
| 左下 | IV / `q4` | 不重要、不紧急 |
| 右下 | III / `q3` | 不重要、紧急 |

用户通过放置卡片表达判断；当前没有截止日期计算、自动优先级推断或自动排程。象限内坐标只表示用户安排的空间位置，不把“更靠右上”解释为更高分数或不同优先级。

小卡片默认只展示标题和驻留时间；点击后在详情中呈现描述、分类、各象限驻留分布、过程记录及操作。准备区显示累计象限驻留，象限卡片显示当前所在象限的累计驻留。信息分层用于减少看板同时展示的内容，不意味着被收起的信息被删除。

准备区承接尚未分类、新建、调整后和恢复后的卡片。准备区不累计驻留。随机纸色、角度和小符号只影响外观，不改变重要性、状态或时间统计。

## 自由摆放、尺寸变化与整理

- 每张卡片的 `positions` 按 `q1`—`q4` 分别保存可选 `{ x, y }`，取值为 `[0, 1]`。它表示扣除卡片尺寸及边缘留白后的可用平移空间比例，不是屏幕像素或象限中心点坐标。准备区仍采用托盘排列，不保存自由坐标。
- 拖动过程中显示副本，最终松手成功落入象限才调用模型 `place` 并保存；经过区域或每帧移动不写入业务位置。同象限只改变坐标，不结算、不重置 `startedAt`；实际换位记 `positioned` 事件，相同坐标不重复记事件。
- 跨象限时结算旧象限、启动新象限驻留，并更新目标象限的位置。原象限位置继续保留；通过详情按钮返回曾放置的象限时可以沿用该位置。调整、完成、取消、恢复及历史快照均保留位置数据。
- 窗口尺寸变化时，界面使用当前画布和卡片尺寸重新计算像素位置，不把重算结果回写为新的归一化坐标。可用平移空间为零时沿该轴靠起点排列；保存比例本身不因此归零。很小的可用区域仍需通过响应式尺寸和实际设备检查保证可用性。
- “整理位置”是用户主动触发的网格／轻微错位排列，会更新当前各象限内的位置，不更换象限，也不打断计时。卡片较多、空间有限时仍可能重叠；可继续手动摆放，键盘聚焦会将对应卡片置于前方。它不自动删除或合并重叠事项。
- 仍使用 `version: 1` 与原存储键。旧卡片缺少 `positions` 时加载为 `{}`，由界面暂用默认排列；拖放或整理后才具有对应的保存坐标。读取损坏存档时丢弃整个非法坐标对，保留其他象限的合法位置；模型 API 对非法坐标拒绝整次操作，不静默截断。

编辑窗无论保存、取消或关闭，卡片都在关闭后移到准备区并继续暂停；取消仅放弃文字修改。各象限旧位置仍保留，之后重新拖入时采用本次落点，原有历史快照不会被覆盖。

## 新建与输入

- 标题必填，最多 28 个 Unicode 码点。
- 描述可选，最多 120 个 Unicode 码点。
- 分类必填，支持预置分类和自定义分类；自定义名称最多 12 个 Unicode 码点。
- 前后空白会清理。组合表情可能包含多个码点，不承诺按用户视觉上的“一个字”计数。
- 保存后在准备区生成卡片，并播放当前动效挡位允许的入场反馈。取消新建不生成卡片。

新建时生成的 `appearance` 随卡片保留。调整内容、完成、取消和恢复不重新抽取外观。

## 状态与操作语义

| 动作 | 状态变化 | 驻留处理 | 记录与反悔 |
| --- | --- | --- | --- |
| 放入象限 | `active / prep` 或其他象限 → `active / q1…q4` | 成功落位时结算上一象限并开始新一段；经过区域不改变记录 | 留下移动事件；可再次移动 |
| 同象限挪动／整理 | `active / qN` 保持不变，仅更新该象限坐标 | 原驻留起点连续，不重复结算 | 实际换位留痕；相同坐标不新增事件 |
| 回准备区 | 活动象限 → `active / prep` | 结算并暂停 | 保留累计驻留 |
| 调整 | 活动卡片 → 编辑期间的准备状态 | 进入调整时结算并暂停 | 窗口打开期间卡片暂留于松手终点；保存、取消或关闭后均移入准备区，取消只放弃文字修改 |
| 完成 | `active` → `completed` | 操作确认时结算并冻结 | 保存完整结束快照，进入已完成记录；可恢复 |
| Void / 取消 | `active` → `cancelled` | 操作确认时结算并冻结 | 原因可选，保存取消快照，进入已取消记录；不记作失败分数 |
| 恢复 | 最新结束状态 → `active / prep` | 保留旧累计量，在准备区暂停 | 原结束快照仍保留；再放入象限才继续累计 |

当前模型没有单独的 `editing` 生命周期状态：调整期间仍为 `active`，位置为 `prep`，同时记录 `editing` 事件。记录册只为当前最新且尚未恢复的结束记录提供恢复入口；不是任意历史版本回滚。

## 拖拽与 Void 确认

拖动距离超过约 6 像素后显示拖拽副本。释放位置决定落点；落在区域之外会回到原位。卡片按钮不启动拖拽。拖拽可以通过 `Esc`、指针取消或窗口失焦中止。

Void 的拖拽确认必须同时满足：

1. 指针进入 Void 区域并连续停留满 **1.2 秒**。
2. 界面显示“松手以取消”。
3. 在同一区域松手；此时没有其他弹窗接管操作。

提前松手、移出区域或中止拖拽都不取消；移开后重新进入需要重新计时。1.2 秒是本原型的交互参数，没有研究结果证明它是最佳阈值。

点击卡片也可操作：详情提供分区移动、调整、完成和 Void 按钮。按钮进入 Void 时使用明确确认弹窗，可填写原因；不要求用户完成拖拽或持续悬停。直接点击右侧操作区本身显示说明，不会自动选择某张卡片执行。

## 文字选择

非编辑区域全局禁止文字选择与原生图片/链接拖动；文本输入、textarea 和有效 contenteditable 保留选中、复制与编辑能力。拖拽时不因经过标题或按钮而留下选择高亮。

## 可复用弹窗

`app.js` 的 `openDialog` 统一承载新建/调整、卡片详情、Void 确认、记录册、设置和帮助，提供：

- `role="dialog"`、`aria-modal`、可关联标题及关闭按钮。
- 初始焦点、`Tab` / `Shift+Tab` 的焦点循环、关闭后的焦点恢复。
- `Esc`、关闭按钮和遮罩关闭；存在拖拽时先中止拖拽。
- 单个活动弹窗及滚动锁定。

编辑暂留卡片的归位由统一关闭回调处理，保存、取消、Esc、关闭按钮或遮罩都执行同一准备区归位逻辑。具备这些代码路径不表示已完成屏幕阅读器或所有键盘组合的无障碍验收。

## 动效合同

| 挡位 | 反馈 |
| --- | --- |
| 灵动 `full` | 纸面轻微 3D 倾斜；创建约 390 毫秒弹性缩放；完成约 500 毫秒抖动后缩小消失；调整静态暂留到窗口关闭，再用约 280 毫秒移到准备区；Void 约 780 毫秒较深的烧蚀与灰烬消散 |
| 轻柔 `reduced` | 约 110 毫秒透明度变化，不进行倾斜、抖动、空间转移或粒子运动；编辑时仍静态暂留 |
| 关闭 `off` | 不等待装饰动效，直接显示业务状态变化；编辑时仍静态暂留，关闭后直接出现在准备区 |

默认尊重系统减少动态效果偏好：选择“灵动”且保留跟随系统设置时，系统要求减少运动会使实际挡位变成“轻柔”。用户设置保存在本地。切换挡位会终止并清理进行中的效果，不改变已经提交的业务结果。

调整、完成与已确认的 Void 拖拽，在清理副本前捕获松手位置、尺寸和倾角。调整从该位置保持静态，窗口关闭后移动到准备区；完成在该位置抖动缩小；Void 在该位置烧蚀。轻柔使用淡变，关闭直接切换，但编辑期间的静态暂留在所有档位都保留。通过详情按钮操作时没有拖拽终点，使用原卡位置。原卡象限与驻留快照不会为了动效而临时移动。Void 使用静态黑洞图标，文字标签保留。

动效层只生成不可交互副本，不删除或迁移业务卡片；完成或取消时清理副本、计时器和动画。全局粒子配额最多 60，不做持续闲置漂浮，不使用随机奖励决定结果。拖拽和禁用倾斜期间不应用纸面微倾。

调整采用暂留与归位，完成采用抖动缩小，Void 采用烧蚀，三种反馈分别对应编辑、达成和主动取消。时长与表现是交互参数，不能据此声称心理效果已经得到验证。未关闭编辑窗的静态暂留不会被动效挡位切换清除；正在转移的动画可以立即结束并清理。

`handleAction` 先提交模型变化并尝试持久化，再等待反馈。因此动画耗时不算进操作后的驻留量；存储失败需要依据保存提示处理，不能因看到了成功动画就认为数据安全。

## 驻留、记录册与保存反馈

详情显示各象限驻留量和占比。总驻留为零时占比为零；百分比逐项取整显示可能存在舍入差。驻留跨刷新、关闭网页继续按墙钟时间计算，不能解释为专注时间，多张卡片也可以同时累计。

已完成与已取消分别展示，每次结束保留当时快照。恢复和再次修改不覆盖旧记录。JSON 导出可保留卡片、外观、过程事件、快照和当时驻留统计；当前没有导入界面。

存储读取、写入或其他窗口更新异常时，用显式提示区分“本页仍可操作”和“数据已保存”。当前保护机制及局限见 [架构概览](../architecture/overview.md)。

## 方法论与待验证假设

四象限表达重要性与紧急性的区分；准备区承认未决事项；完成与取消分开表达主动选择；可恢复记录允许重新决定；动效意在提供可见反馈。这些是设计意图，不能据此宣称已经形成习惯、降低焦虑或提高长期执行力。

布局采用视觉层级、共同区域与渐进揭示作为设计依据：用标题和时间形成扫描层级，用象限背景表达分组，把较多信息放入详情。这些是可讨论的界面组织方法，不是本产品有效性的证明。自由摆放借鉴空间记忆研究，见[证据登记 E10](../research/evidence-register.md#e10--空间记忆与自由摆放)；仍需验证查找速度、错误率与整理成本，不能外推为四象限提高执行力或 3D 动画促进习惯。

后续研究可以比较动效强度对理解、误触和操作负担的影响，观察中断后恢复是否更容易。不能只用页面停留时长、点击次数或完成数量证明积极效果。现阶段只按 [验证记录](../quality/validation.md) 判断软件行为是否正确。
