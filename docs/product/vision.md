# 产品愿景：把时间与金钱用于自己认可的生活

- 文档日期：2026-11-08
- 状态：依据用户原始想法与本轮讨论重建的产品提案；不代表以下所有功能已经批准实施。
- 当前实现：仅有四象限便利贴静态交互原型，参见 [原型说明](../../README.md)。
- 相关文档：[产品需求](requirements.md)、[能力路线图](roadmap.md)、[研究证据登记表](../research/evidence-register.md)。

## 1. 想解决的问题

这是一项长期的个人管理与记账工具计划，目标运行于网页端，未来以 Python 承担业务与数据内核。现有 HTML/CSS/JavaScript 原型用于验证交互，并不代表 Python 后端、日程系统或账本已经存在。

产品希望帮助使用者回答三个相互关联的问题：

1. 我现在在意什么，哪些事情值得进入生活？
2. 我的时间和金钱实际流向了哪里，是否与这些选择一致？
3. 面对资源与环境限制，下一步怎样调整才可执行？

个人管理与记账通过共同的目标、项目和生活事项关联。时间与金钱始终是独立维度，不换算成统一的人生分数，也不以花费越少、工时越长或完成件数越多定义生活质量。

## 3. 产品立场

### 3.1 让价值选择先于效率排名

生命有限是一种观察视角，不是持续催促的倒计时。月份可以记录工作、学习、关系、照护、休息和探索，不因为没有生产性成果就标记为失败。默认不推算个人死亡日期；未来月格表示规划视野，不表示寿命预测。

“重要”应有使用者自己的理由，而不是由系统根据截止日期、金额或历史点击推断。价值导航可以帮助人表达意图，但不应要求先完成一套冗长的人生测评才能记一笔账或创建事项。

### 3.2 反馈服务于判断与行动

交互反馈应让使用者知道刚才发生了什么、现在处于什么状态、如何撤销。完成、调整、暂停和取消具有不同语义；取消是重新选择的一种结果，应当保留过程而不进行羞辱。

卡牌的随机纸色、角度、符号与粒子属于美术。随机性不改变事项价值、账目金额、计时、完成判定或操作结果；不引入抽奖奖励、损失惩罚和为了保持连续天数而强迫打开产品的机制。

### 3.3 允许中断与重返

工具需要适应忙碌、收入变化和生活意外。中断后可以从当前状态继续，不必先补齐所有历史空白。未记录应当被标记为未知，不能自动解释为没有活动或没有支出。

未来记账模块可以提供分步核对、暂缓处理与简洁摘要；这些属于待验证的减负设计。摘要应清楚标出数据覆盖范围和不确定性，不能为了让人感觉轻松而隐瞒已知账单或风险。

### 3.4 真实结果比产品使用量更重要

首要目标是帮助使用者做出认可的选择、执行重要事项、了解资源状况并减少维护负担。打开次数、停留时长与完成卡片数只能作为过程信号，不能单独代表成功。

如果一种动效受欢迎但不改变长期行为，可以保留为审美与体验价值；不需要把它包装成经过科学证明的行为干预。个人试用中的改善也不自动具有对其他使用者的普遍性。

## 4. 概念与证据如何进入产品

以下是设计对应关系，不是本产品效果已被验证的声明。具体论文、研究类型、结论和局限集中维护于 [研究证据登记表](../research/evidence-register.md)，避免多个文档分别维护相互冲突的证据摘要。

| 模块 | 概念或方法依据 | 本产品需要另行检验的问题 |
| --- | --- | --- |
| 生命月历与人生章节 | 有限性、未来自我连续性、时间视野与目标选择 | 月格能否帮助形成有用回顾和未来行动；是否增加压力或回避 |
| 价值与目标导航 | 自我一致目标、自主选择、价值澄清 | 简短表达“为什么在意”能否改善实际选择；是否增加录入负担 |
| 矩阵与行动计划 | 紧迫性偏差、实践判断、实施意图、目标进度监测 | 矩阵是否优于普通清单；动态变化是否清楚；重要而不紧急的事是否获得行动时间 |
| 卡牌与语义反馈 | 自主性、能力感、反馈与游戏化研究 | 动效是否帮助理解与满意度；是否诱导刷简单任务；长期作用是否存在 |
| 记账、预算与核对 | 自我监测、心理账户、财务信息回避 | 能否减少重复录入与核对成本，并提高账目理解；是否产生新的回避或过度限制 |
| 时间与金钱联动 | 机会成本、跨期选择、未来自我连续性 | 并列观察两种资源能否改善项目决策；不能从机制证据直接推出联动界面有效 |
| 回顾、暂停与重返 | 自我调节反馈、实施意图、习惯的情境依赖 | 能否降低中断后的恢复成本，并帮助调整现实中的行动 |

新模块进入实现前，应先形成一张证据卡：用户问题、概念依据、相关研究、适用人群与情境、支持与不支持的说法、产品假设、验证指标及退出条件。研究空缺不应被隐去；可以进入明确标注的探索性原型，但不能对外宣称已获验证。

## 5. 差异化方向

本轮提案不声称“首次创新”或“别人从未做过”。值得探索的是以下组合能否解决真实问题：

- **同一事项连接时间与金钱。** 例如一次学习计划同时关联课程预算、日程、实际支出、实际学习记录与阶段回顾，而不是在两套工具中重复描述。
- **完成留下人生语境。** 卡片从矩阵中结束后，成果可以进入对应月份；取消也保留当时的选择，避免只有成功才值得记录的倾向。
- **事前预期与事后体验相对照。** 用户可以自愿记录某个项目希望获得什么，再在较低频率的回顾中判断是否值得继续；不要求逐笔消费做心理问卷。
- **允许调整资源承诺。** 放弃或缩小项目时，释放尚未发生的时间安排和预算预留，同时保留已经发生的事实。
- **减少维护而不伪造完整性。** 合理默认值、重复项目复用、去重与分批确认优先于复杂报表；缺失的数据明确显示为待核对。

这些方向目前属于产品假设，尚无本产品的用户研究结果证明其差异化价值。

本项目公开的内容应是代码、产品文档、研究引用和明确标注的合成示例。真实账单、私人日程、浏览器记录导出、身份资料与密钥不属于公开项目素材。上传项目不等于授权上传使用者的个人数据。

## 7. 尚待确认

- 首版主要服务本人，还是同时为其他个人使用者设计。
- 生命月历的默认时间范围、过去记录粒度，以及首页中月历与日常行动区的比例。
- 记账首先要支持的币种、账户类型、录入渠道与账单格式。
- Python 内核采用本机运行还是受控部署；数据保存、备份与跨设备需求。
- 动效偏好、回顾频率和可接受维护时间，需要通过实际体验确定，不能提前写成已批准的指标。

这些问题不改变核心方向：让工具帮助人选择与调整，同时保留其自主性和事实记录。
