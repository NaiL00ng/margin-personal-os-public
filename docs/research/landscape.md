# 竞品结构与设计灵感

核验日期：2026-11-08。以下为六个相关产品的非穷尽比较，依据官方功能页或开发者发布说明；没有完成所有付费版本、平台和长期使用场景的实测。官方功能描述只能证明产品宣称提供什么，不能证明它改善生活。表中的优点与局限是项目设计分析，区别于论文结论；学术依据另见[研究证据登记表](evidence-register.md)。

## 个人管理

| 产品与已核验结构 | 可借鉴之处 | 局限、取舍与本项目判断 |
| --- | --- | --- |
| **Todoist**：任务、项目、子任务、标签与优先级；自然语言快速输入；列表、日历和看板视图；完成记录、趋势与 Karma。来源：[官方功能页](https://www.todoist.com/features)。 | 一个任务对象投影到多个视图，输入与日常查看路径清晰。 | 分类、优先级和日期仍需要用户维护；完成数量未必代表人生目标的推进，这是指标解释边界。可借鉴快速输入和视图一致性，避免把积分当作人的价值。 |
| **TickTick**：任务、标签、日历与多种视图；已有艾森豪威尔矩阵、习惯追踪、番茄钟、倒数日及统计。来源：[官方功能页](https://ticktick.com/features)。 | 已把任务、日程和重复行为放在同一产品中，是本项目应认真比较的直接参照。 | “矩阵 + 日程 + 习惯”并非新功能组合。功能丰富可能带来配置和切换成本，但需要用户研究验证。本项目应验证动态操作是否更清楚，而不能仅凭动画宣称优于它；象限驻留也不等于其番茄钟记录。 |
| **Habitica**：习惯、重复日常事项和一次性待办，连接角色、经验、金币、物品及组队任务。来源：[开发者官方商店说明](https://play.google.com/store/apps/details?id=com.habitrpg.android.habitica)。 | 行动反馈具有明确叙事和可辨识的进程，游戏身份可承载情感联系。 | 游戏系统也要学习和维护；奖励数量可能改变用户对任务的选择，这属于待验证风险，不能断言对所有用户有害。本项目可借鉴反馈的连贯性，先不引入等级经济、连胜压力或竞争。 |

这三类产品的共同结构是“任务对象 → 时间与分类视图 → 完成记录／反馈”。差异主要在捕获成本、排程能力、反馈机制和维护负担；可视化换皮不自动构成行为层创新。

## 记账与预算

| 产品与已核验结构 | 可借鉴之处 | 局限、取舍与本项目判断 |
| --- | --- | --- |
| **YNAB**：围绕已有资金的用途分配、类别、目标和交易组织计划，强调使支出与个人优先事项一致；提供 Fresh Start，旧计划可归档保留，新计划可继承部分结构。来源：[官方理念说明](https://www.ynab.com/guide/what-is-spendfulness)、[官方重启说明](https://support.ynab.com/plan-resets-and-fresh-starts-HkXYR_c0q)。 | 将预算变成事前选择，且允许调整与重新开始；“保留过去、从现在继续”已有成熟相邻实践。 | 类别和预算规则存在学习、维护成本，具体负担需实测。“低羞耻重返”不能仅凭重启按钮宣称首创；本项目应更具体地验证缺口说明、恢复步骤和情绪负担。 |
| **Actual Budget**：本地优先的信封预算；账户、交易、拆分、关联转账、导入与报告；可离线使用，另有可选同步和加密能力。来源：[官网](https://actualbudget.org/)、[官方文档](https://actualbudget.org/docs/)。 | 预算分配与实际交易各有明确语义；CSV 等导入与数据掌握能力，适合个人自用的渐进实现。 | 自行部署和同步会引入备份与运维责任；本地优先也不自动保证备份完备或所有威胁下安全。当前应优先手动／CSV 与可追溯账目，避免先建设复杂银行连接。 |

记账产品的基础结构通常是“账户 → 实际交易 → 分类／预算 → 核对与回顾”。需要区分两种负担：记录和核对的操作成本，以及面对结果时的心理成本。自动导入可能降低前者，却仍需处理重复、误分类、信任和修复；本项目对这些痛点的具体程度尚需访谈或自用记录，不能从通用文献推算用户占比。

## 1in8b 与生命格子的来源边界

本次找到自称官方的 [1 in 8 Billion / 1in8b.life](https://1in8b.life/)，可核验其模拟出生背景、逐年焦点、人生决策与记录等结构。页面当前明确标注 **Life map：1 square = 1 year**。因此，本项目拟采用的“每月一个方格”应记录为本项目的改编，不能写成已核验的原作月格功能。

用户所指的具体链接与版本仍待确认。该站点自述使用公开统计数据，本次没有验证其模拟模型、参数或预测效度；模拟人生也不构成对真实个人寿命的预测。可以借鉴阶段感、回看和人生事件的叙事组织，但不能由游戏感染力推导真实用户会更幸福或更自律。

## 本项目可以提出的差异化假设

本项目的机会在于把任务、日程、资金用途和回顾连接到同一个“承诺”，并验证这种连接是否减少脱节。以下均为设计假设，不宣称全球首创。

| 方向 | 具体行为 | 与既有产品的关系与检验重点 |
| --- | --- | --- |
| **可兑现的时间—金钱承诺** | 为课程预留资金时，同时安排首次学习；支付后记录实际支出，回顾是否真的学习。 | 预算、任务和日历都已有成熟实现；重点检验它们的关联是否提高兑现率，而非多显示一个仪表盘。预留与支付不得重复扣减。 |
| **保留历史的温和重返** | 中断后展示可信余额、缺失范围和一个下一步；取消／恢复保留当时快照，不要求先补完所有历史才能继续。 | YNAB Fresh Start 已是相邻实践。应检验恢复所需精力、羞耻感和准确性；不能隐藏重要财务风险，也不应美化为所有中断都有益。 |
| **低打扰的选择性核对** | 优先提示无法匹配、疑似重复或与计划差异大的事项；允许用户设定提示频率。 | 自动分类与交易核对属于既有产品领域。区别须落实为减少多少无效核对、是否漏掉异常，不能只用“智能”命名。 |
| **可解释、可撤回的交互反馈** | 清楚区分完成、取消和调整；动效强度可选，历史可回看。 | 游戏化、任务归档、动效和撤回都不是新概念。本项目需验证组合是否减少误操作并帮助理解状态；视觉偏好与长期效果分别评价。 |

## 从原型到后续模块的约束

当前[静态原型](../../README.md)实现的是四象限卡片及其过程记录，没有银行连接、完整记账或 Python 后端。后续无论采用何种视觉形式，都应保持以下概念清楚：

- 重要性是用户的判断，紧迫性有日期与后果依据；不要把离截止日期近自动解释为更重要。
- 象限驻留是状态经过的墙钟时间，多张卡片可以并行累计；它不证明实际努力或目标进度。
- 预留资金是计划，支付是交易，退款是关联原交易的新事实；取消日程不能抹掉已经发生的支出。
- 生命月格是导航与回顾视图，不能以人口平均寿命给个人制造确定的死亡截止日期。
- 声称有效之前，补充对应模块的直接研究与实际验证。竞品功能、哲学概念、通用机制和本项目效果四者分别陈述。

待确认事项包括用户所指 1in8b 版本、真实记账负担与回避场景、不同设备的交互体验，以及长期使用结果。本次比较不覆盖整个市场，也不足以支持“别人没有做过”的结论。
